§ 01

Component-local state

The $state rune wraps values in a Proxy. Mutations to objects and arrays are tracked — no more reassignment dance.

Svelte 4 component.svelte
<script>
  let count = 0;
  let user = { name: 'Ada', age: 30 };
  let items = [];

  function increment() {
    count += 1;
    user.age += 1;
    // works, but reassignment was safer:
    // user = { ...user, age: user.age + 1 }
    items = [...items, 1];
    // had to reassign arrays
  }
</script>
Svelte 5 component.svelte
<script lang="ts">
  let count = $state(0);
  let user = $state({ name: 'Ada', age: 30 });
  let items = $state<number[]>([]);

  function increment() {
    count += 1;
    user.age += 1;       // proxy-tracked, just works
    items.push(1);       // mutation works too
  }
</script>
Key shift

$state() wraps the value in a proxy. Mutations to objects and arrays are tracked automatically — no more reassignment dance.

§ 02

Derived values

$derived is lazy and cached. It only re-runs when its dependencies change — your default for anything computed.

Svelte 4
<script>
  let count = 0;
  $: doubled = count * 2;
  $: parity = count % 2 === 0
    ? 'even'
    : 'odd';
</script>
Svelte 5
<script lang="ts">
  let count = $state(0);
  let doubled = $derived(count * 2);
  let parity = $derived(
    count % 2 === 0 ? 'even' : 'odd'
  );

  // Multi-statement version:
  let summary = $derived.by(() => {
    const d = count * 2;
    return `${count} doubled is ${d}`;
  });
</script>
§ 03

Side effects

$effect runs only in the browser, after DOM updates. Use it for DOM sync, subscriptions, timers, or fetches tied to state — not for computing values.

Svelte 4
<script>
  let count = 0;
  $: console.log('count is', count);
  $: if (count > 10) alert('high!');
</script>
Svelte 5
<script lang="ts">
  let count = $state(0);

  $effect(() => {
    console.log('count is', count);
  });

  $effect(() => {
    if (count > 10) alert('high!');
  });

  // With cleanup (intervals, listeners):
  $effect(() => {
    const id = setInterval(() => count++, 1000);
    return () => clearInterval(id);
  });
</script>
Important

Don't reach for $effect to compute values — that's $derived's job. Use effects only for things that do something in the outside world.

§ 04

Component props

Props are now destructured from $props(). TypeScript inference is dramatically better — props, generics, and snippet typing all just work.

Svelte 4
<script>
  export let name;
  export let age = 0;
  export let onSave = () => {};
</script>
Svelte 5
<script lang="ts">
  interface Props {
    name: string;
    age?: number;
    onSave?: (data: string) => void;
  }

  let {
    name,
    age = 0,
    onSave = () => {}
  }: Props = $props();
</script>

For two-way binding from a parent, use $bindable():

Svelte 5 bindable prop
let { value = $bindable() }: { value?: string } = $props();
§ 05

Stores — the big one

In Svelte 4, stores were the answer to "share state across components." In Svelte 5, runes mostly replace that need. Put $state in a regular module and export it.

Svelte 4 stores.js
import { writable, derived } from 'svelte/store';

export const count = writable(0);
export const doubled = derived(count, $c => $c * 2);
Svelte 4 component.svelte
<script>
  import { count, doubled } from './stores.js';
  count.update(c => c + 1);
</script>

<p>{$count} {$doubled}</p>

Svelte 5 — the new way uses a .svelte.ts file, which tells the compiler "runes allowed here." Plain .ts files cannot use runes.

Svelte 5 counter.svelte.ts
export const counter = $state({ value: 0 });

export const stats = $derived.by(() => ({
  doubled: counter.value * 2,
  parity: counter.value % 2 === 0 ? 'even' : 'odd'
}));
Svelte 5 component.svelte
<script lang="ts">
  import { counter } from './counter.svelte.ts';
</script>

<button onclick={() => counter.value++}>+</button>
<p>{counter.value}</p>

Class-based stores — a pattern worth adopting

This is, arguably, the single biggest ergonomic win of Svelte 5. No $store prefix, no .update()/.set() ceremony, full TypeScript autocomplete.

Svelte 5 dashboard.svelte.ts
class DashboardState {
  cpuTemp = $state(0);
  unreadEmails = $state(0);
  jobApps = $state<JobApp[]>([]);

  totalAlerts = $derived(
    (this.cpuTemp > 80 ? 1 : 0) +
    (this.unreadEmails > 50 ? 1 : 0)
  );

  addJobApp(app: JobApp) {
    this.jobApps.push(app);
  }
}

export const dashboard = new DashboardState();
Svelte 5 any-component.svelte
<script lang="ts">
  import { dashboard } from './dashboard.svelte.ts';
</script>

<p>CPU: {dashboard.cpuTemp}°C</p>
<p>Alerts: {dashboard.totalAlerts}</p>
When to still use classic stores

The svelte/store module still works fine. Use it for interop with libraries that expect a store contract, or for readable/custom stores with subscribe semantics. For new app state, prefer runes.

§ 06

Effects & untracking

When you need to read state inside an effect without subscribing to it, reach for untrack.

Svelte 5
import { untrack } from 'svelte';

let a = $state(0);
let b = $state(0);

$effect(() => {
  console.log(a, untrack(() => b));
  // re-runs on `a` only
});
§ 07

Event handlers

Worth flagging since it touches every component you'll write.

Svelte 4
<button on:click={handler}>
  Click
</button>

<form on:submit|preventDefault={save}>
  ...
</form>
Svelte 5
<button onclick={handler}>
  Click
</button>

<form onsubmit={(e) => {
  e.preventDefault();
  save();
}}>
  ...
</form>

Modifiers (|preventDefault, |stopPropagation) are gone. Call those methods inline on the event object instead.

§ 08

Mental model summary

The whole migration, in one table. Pin it somewhere visible while you build.

Concept Svelte 4 Svelte 5
Local mutable state let x = 0 let x = $state(0)
Computed value $: y = x * 2 let y = $derived(x * 2)
Side effect $: doSomething(x) $effect(() => doSomething(x))
Props export let foo let { foo } = $props()
Two-way bindable prop export let foo let { foo = $bindable() } = $props()
Shared state writable(0) in .js $state(0) in .svelte.ts
Derived store derived(s, fn) $derived(...) in .svelte.ts
Event handler on:click onclick

Two rules to keep you out of trouble

i.

$derived is your default for anything computed. Reach for $effect only for DOM sync, subscriptions, or external side effects.

ii.

Shared state belongs in a .svelte.ts (or .svelte.js) file — not a plain .ts. The compiler needs that extension to enable runes.
